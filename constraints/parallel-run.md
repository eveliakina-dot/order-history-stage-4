# Order history suite — parallel run

## Context

The TechShop E2E order-history regression suite runs on **4 parallel workers** in CI. It covers filtering by status, filtering by date range, pagination, opening an order's details, and the empty state for a user with no orders. One worker also registers a new account and places its first order, to cover the "first order appears in history" path.

## The suite (4 workers)

| Worker | Tests |
|---|---|
| W1 | filter_by_status, filter_by_date_range, paginate_to_second_page, view_order_details, empty_state_no_orders |
| W2 | filter_by_status, filter_by_date_range, paginate_to_second_page, view_order_details, empty_state_no_orders |
| W3 | filter_by_status, filter_by_date_range, paginate_to_second_page, view_order_details, empty_state_no_orders |
| W4 | filter_by_status, filter_by_date_range, paginate_to_second_page, view_order_details, empty_state_no_orders, register_and_place_first_order |

Each test needs: a user to log in as, and — depending on the test — a status to filter on, a date range, an expected order count or order number, or nothing (empty state).

## System constraints (facts about TechShop's database and API — treat as given)

| Field / resource | Constraint |
|---|---|
| `user.email` | UNIQUE in the `users` table; registering an existing email returns `422 email_already_in_use` |
| `history.fixture@orders.test` | Seeded account with exactly 25 orders across all statuses, for pagination and filter tests. **Read-only**: any test that places, changes or cancels an order for this account corrupts every other worker's counts |
| `order_number` | Generated by the database on `POST /orders`. The value is not known before the order exists — a test reads it from the response, never sends it |
| Empty-state user | `empty_state_no_orders` needs a user with **zero** orders. If any test places an order for that user, the empty-state assertion fails |
| `order.status` | One of the `OrderStatus` enum values (`pending`, `confirmed`, `processing`, `shipped`, `delivered`, `cancelled`). An order can be modified or cancelled only while `pending`; afterwards any change returns `409 order_not_modifiable` |
| Pagination | 10 orders per page; `nextPage` is `null` on the last page |
